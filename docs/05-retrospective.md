# 项目复盘

## 难点

文档冲突与部分读取失败需要分别处理。D01规定30天，D02规定15天，必须读取相关原文并列出冲突；若D02读取失败，则保留D01并返回工具失败。

实现中将检索、原文读取和最终回答分开，以任务状态保存已读证据，并通过Trace记录每一步的结果。

## 改进

纯字面检索对“住店”“宾馆”“无线网”没有命中。增加同义词归一化后，4条查询的目标文档命中由1条提升到4条。

引用校验统一放在执行器中，检查文档、片段和原文。无效决策计入步骤预算，使异常路径也能按上限结束。

## 收获

工具调用、业务结果和任务状态应分别记录。工具执行成功后，仍需核对证据是否充分；后续步骤失败时，已有结果应继续保留。将决策后端与工具解耦，有利于复用同一组测试验证不同后端。

## 下一步

1. 接入真实模型，记录模型根据工具结果选择后续动作的过程。
2. 运行正常、冲突、资料不足和工具失败场景。
3. 扩充问题改写与适用范围不同的文档，改进检索和冲突判断。
