# 需求分析

## 用户与目标

面向查询制度或产品问题的员工，根据资料给出有出处的回答，并指出资料冲突和缺口。

## 输入与输出

输入：问题、可选对话历史，以及带文档ID、版本日期和适用范围的合成资料。

输出：回答、引用文档ID与原文片段、资料缺口、任务状态和执行Trace。

## 实现范围

采用Python CLI，提供文档检索和原文读取两个本地工具，以规则型Mock运行“选择动作—执行工具—观察结果—选择下一动作”的循环。

覆盖明确答案、文档冲突、资料外问题、改写问题、上下文追问和工具失败六类场景，并增加失败恢复、文档替换、执行上限和引用校验。

## 成功标准

1. 明确答案附文档ID、版本日期和原文引用。
2. D01规定30天、D02规定15天时，同时列出两条规定并请求确认适用制度。
3. 资料不足返回`insufficient_evidence`，问题对象缺失返回`needs_clarification`。
4. 改写问题和上下文追问能找到对应资料。
5. 工具失败按可重试性处理，保留已成功读取的证据。
6. 达到步骤或工具调用上限返回`incomplete`。
7. 输入、实际输出和执行记录可通过命令复现。
